# Page Patterns

## Purpose

Define repeatable page structures so the prototype feels like one product rather than disconnected screens.

## 1. Dashboard Pattern

Structure:

- Compact page header
- Primary KPI band
- Main analytical area
- Actionable work queue
- Secondary insights
- Recent activity

Rules:

- Do not use a grid of identical cards.
- Prioritize decisions and exceptions over decorative metrics.
- Role-specific content changes without changing the overall visual language.

## 2. List Pattern

Used for requests, tasks, and deposits.

Structure:

- Page header and primary action
- Summary strip
- Search and filters
- Saved views
- Data table or purpose-built list
- Pagination
- Optional preview drawer

Rules:

- Filters remain visible when relevant.
- Returning from details preserves list state.
- Rows emphasize the most decision-relevant fields.

## 3. Transaction Workspace Pattern

Used for investment requests.

Structure:

- Case header
- Workflow progress
- Contextual section navigation
- Main content area
- Sticky summary panel
- Sticky action bar

Rules:

- Avoid long one-page forms.
- Each section has a clear completion state.
- Actions reflect role, status, and readiness.

## 4. Detail Record Pattern

Used for deposit details.

Structure:

- Record identity and status
- Key financial facts
- Contextual tabs
- Timeline and related request
- Documents and history

## 5. Review Pattern

Used for approvals, support, finance, and accounting review.

Structure:

- Decision summary
- Key facts and risks
- Supporting evidence
- Previous decisions
- Comment field
- Approve, return, reject actions

The reviewer must see enough context without navigating through every editable section.

## 6. Report Pattern

Structure:

- Report title and purpose
- Date and scope filters
- KPI summary
- Primary visualization
- Supporting table
- Export placeholder where appropriate

## 7. Settings Pattern

Structure:

- Settings category navigation
- Focused configuration panel
- Save or reset actions
- Explicit warnings for destructive demo actions

## Common Page Rules

- One obvious primary action.
- Consistent page margins and content widths.
- Clear loading, empty, no-results, and error states.
- Avoid nesting several card containers.
- Use section dividers and whitespace instead of decorative boxes.
