# AI Review Checklist

Use this checklist before declaring any page or component complete.

## Requirements and scope

- [ ] Relevant business documentation was read.
- [ ] Relevant page specification was read.
- [ ] No business rule, role, field, state, or approval was invented.
- [ ] Prototype limitations remain respected: no backend, API, or authentication.

## Brand and visual quality

- [ ] Environment Fund colors and approved assets are used correctly.
- [ ] The screen is Arabic-first and fully RTL.
- [ ] The design feels institutional, premium, calm, and financially trustworthy.
- [ ] The screen does not resemble a generic admin template.
- [ ] Visual hierarchy is immediately understandable.
- [ ] Spacing, alignment, typography, and component proportions are consistent.
- [ ] Patterns and graphic elements are restrained and do not reduce readability.
- [ ] Color is not the only indicator of status or risk.

## UX and content

- [ ] The primary user goal is clear.
- [ ] The current status and next action are visible where applicable.
- [ ] Arabic labels are natural, concise, and consistent.
- [ ] Empty, loading, error, success, and disabled states are covered.
- [ ] Destructive or irreversible actions require confirmation.
- [ ] Tables, forms, and filters are not unnecessarily dense.
- [ ] Financial figures are formatted consistently.

## Responsive behavior

- [ ] Desktop layout is intentionally designed.
- [ ] Tablet layout is intentionally adapted.
- [ ] Mobile layout is not merely a compressed desktop screen.
- [ ] Tables have an approved mobile behavior.
- [ ] Drawers, dialogs, and sticky actions remain usable.
- [ ] No unintended horizontal overflow exists.

## Code quality

- [ ] TypeScript is strict and no unsafe `any` was introduced.
- [ ] Components have clear responsibilities.
- [ ] Shared components are reused appropriately.
- [ ] No unnecessary dependency was added.
- [ ] No broken imports, dead code, or duplicate logic remains.
- [ ] No console, lint, or type errors remain.
- [ ] Accessibility and keyboard behavior were reviewed.

## Final visual inspection

Review the page at realistic content volume, not only with ideal short values. Confirm that long Arabic labels, large monetary values, many workflow steps, attachments, and empty states remain visually balanced.
