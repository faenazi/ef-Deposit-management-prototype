# تنفيذ المرحلة 06: المراجعة النهائية لجودة الواجهة

## الهدف
إجراء مراجعة شاملة للنموذج الأولي بعد اكتمال الصفحات، وإصلاح العيوب الوظيفية والبصرية والتجاوبية دون توسيع النطاق أو إعادة بناء التطبيق من الصفر.

## اقرأ قبل التنفيذ
1. `CLAUDE.md`
2. جميع ملفات `docs/07-brand-experience/`
3. جميع ملفات `docs/08-design-specifications/`
4. جميع ملفات `docs/09-ai-governance/`
5. راجع جميع Prompts المنفذة تحت `prompts/04-frontend/`.

## منهج العمل
1. افحص التطبيق الحالي كاملًا قبل التعديل.
2. أنشئ قائمة ملاحظات مرتبة حسب الخطورة.
3. أصلح العيوب الحرجة ثم العالية ثم المتوسطة.
4. لا تغيّر المتطلبات أو تضف ميزات جديدة أثناء المراجعة.
5. أعد تشغيل التحقق بعد كل مجموعة إصلاحات رئيسية.

## محاور المراجعة
### 1. سلامة الأعمال
تحقق من:
- بقاء الطلب مسودة أثناء الإعداد التدريجي.
- عدم بدء الاعتماد قبل الإرسال.
- تطبيق حد 100 مليون ريال بدقة.
- صحة مساري الاعتماد.
- الإرجاع بسبب إلزامي وحفظه في السجل.
- استخدام حالة `معاد للاستكمال` عند الإرجاع.
- صحة مراحل دعم الاستثمار والمالية والمحاسبة والتفعيل.
- إنشاء الوديعة النشطة من الطلب المكتمل فقط.

### 2. الصلاحيات
راجع كل دور على حدة:
- ما يراه.
- ما يمكنه تعديله.
- ما يمكنه اعتماده أو إعادته.
- المسارات التي يمكنه الوصول إليها.
- عدم ظهور إجراءات غير مخولة ولو كانت disabled بلا حاجة.

### 3. الجودة البصرية
راجع كل صفحة وفق المعايير التالية:
- hierarchy واضح.
- إجراء أساسي واحد ظاهر.
- توازن المساحات والكتل.
- عدم ازدحام البطاقات.
- الجداول احترافية وقابلة للمسح البصري.
- الحالات والرسائل مفهومة دون اعتماد على اللون وحده.
- الهوية واضحة لكن غير مزعجة.
- عدم وجود مظهر generic admin أو AI-generated dashboard.
- ثبات typography والمسافات والحدود والظلال.
- عدم وجود عناصر تبدو unfinished أو placeholder.

أي شاشة تعمل ولكن تبدو عامة، مزدحمة، أو غير متوازنة تعتبر غير مكتملة ويجب تحسينها.

### 4. العربية وRTL
تحقق من:
- اللغة العربية الطبيعية والمهنية.
- اتجاه layout والمكونات صحيح.
- الأيقونات الاتجاهية صحيحة.
- محاذاة الأرقام والمبالغ والنسب والتواريخ واضحة.
- عدم انقلاب ترتيب breadcrumb أو timeline أو pagination.
- عدم وجود نصوص إنجليزية غير مقصودة في الواجهة.

### 5. Responsive
اختبر على مقاسات ممثلة لـ:
- 1440px.
- 1280px.
- 1024px.
- 768px.
- 390px.

تحقق من:
- عدم وجود overflow غير مقصود.
- عدم تداخل header/sidebar/content.
- سهولة استخدام drawers/dialogs على الجوال.
- تحويل الجداول المعقدة بطريقة مفهومة.
- بقاء الإجراءات المهمة مرئية دون تغطية المحتوى.
- أحجام لمس مناسبة.

### 6. Accessibility
تحقق من:
- keyboard navigation.
- focus visibility.
- labels صحيحة للنماذج.
- aria labels للأزرار ذات الأيقونات فقط.
- contrast مناسب.
- dialogs تحجز focus وتعيده بصورة صحيحة.
- رسائل validation مرتبطة بالحقول.
- احترام reduced motion عند الإمكان.

### 7. الحالات والتفاعل
تحقق من وجود وعمل:
- loading.
- empty.
- error وretry.
- permission denied.
- validation.
- confirmation.
- success feedback.
- disabled and pending actions.
- حفظ التغييرات ومنع النقر المكرر.

### 8. جودة الكود
راجع:
- عدم وجود `any` غير مبرر.
- عدم تكرار قواعد العمل.
- عدم استيراد fixtures مباشرة في UI.
- عدم وجود مكونات ضخمة يمكن تقسيمها بوضوح.
- عدم وجود ملفات ميتة أو imports غير مستخدمة.
- عدم وجود console logs أو TODOs حرجة.
- اتساق naming وهيكل features.
- عدم وجود أسرار أو إعدادات نشر.

### 9. الأداء
- راجع حجم الحزم دون تحسينات مبالغ فيها.
- lazy load للصفحات الثقيلة عند الحاجة.
- منع re-renders الواضحة غير الضرورية.
- عدم توليد البيانات الكثيفة في كل render.
- charts والجداول لا تسبب تجمدًا ملحوظًا.

## أوامر التحقق الإلزامية
من داخل `/src` شغّل:

```bash
npm run typecheck
npm run lint
npm run build
```

وشغّل أي اختبارات موجودة في المشروع. أصلح جميع الأخطاء الناتجة عن التنفيذ.

## التسليم النهائي
أنشئ أو حدّث ملفًا داخل الوثائق باسم مناسب لتقرير المراجعة، يتضمن:
- ملخص النطاق.
- المشكلات التي اكتشفت.
- الإصلاحات التي نُفذت.
- المسائل المتبقية إن وجدت مع سبب واضح.
- نتائج الأوامر.
- قائمة السيناريوهات والأدوار التي تم فحصها.

لا تدّع اختبار شيء لم يتم اختباره فعليًا.

## Definition of Done
لا تعتبر المراجعة مكتملة إلا إذا:
- لا توجد أخطاء build أو type أو lint.
- المسارات الأساسية تعمل end-to-end.
- كل دور تمت مراجعته.
- Desktop وTablet وMobile قابلة للاستخدام.
- التصميم متماسك وجميل ويبدو مخصصًا لصندوق البيئة.
- لا توجد ميزات خارج نطاق النموذج الأولي.
